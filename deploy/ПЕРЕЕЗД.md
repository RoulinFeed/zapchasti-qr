# Переезд на новый сервер 5.182.87.217

Всё делается один раз, примерно за 20 минут. Старый сервер не выключайте, пока не проверите новый.

## 0. Перед началом: собрать данные с телефонов

Всё, что механики отсканировали без связи, пока лежит только у них в телефонах. Перед переносом базы попросите всех открыть приложение там, где есть интернет, и дождаться, пока вверху пропадёт значок «не отправлено: N». Что придёт на старый сервер после переноса, на новый не попадёт.

## 1. Ключ для автообновления

Новый сервер = новый ключ, старый лучше не переносить. На своём компьютере (Windows, PowerShell):

```powershell
ssh-keygen -t ed25519 -f $HOME\.ssh\zapchasti_deploy -N '""'
```

Получится два файла:
- `zapchasti_deploy.pub` — **открытый** ключ, его вставляете в скрипт на сервере (шаг 2);
- `zapchasti_deploy` — **закрытый** ключ, его вставляете только в секрет `DEPLOY_KEY` на GitHub (шаг 3). Никуда больше его не отправляйте, в чат тоже.

## 2. Настройка сервера

Зайдите на новый сервер под root (`ssh root@5.182.87.217`) и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/RoulinFeed/zapchasti-qr/main/deploy/setup-server.sh -o setup.sh
bash setup.sh
```

Скрипт:
1. включит подкачку 2 ГБ (без неё 1 ГБ памяти мало для базы и приложения);
2. поставит Docker;
3. создаст пользователя `deploy` и попросит **открытый** ключ из шага 1;
4. создаст папку `/home/deploy/zapchasti-qr`;
5. спросит, откуда взять данные. Вариант 1 сам заберёт со старого сервера базу, фото и `.env` (спросит адрес старого сервера и его пароль). Если старый сервер уже недоступен, выберите 2 и укажите файлы из папки `backups/`, которые вы заранее скопировали на новый сервер;
6. запустит базу и загрузит в неё данные. Приложение пока не запускается.

## 3. Секреты на GitHub

GitHub → репозиторий `zapchasti-qr` → Settings → Secrets and variables → Actions. Поменять (кнопка с карандашом у каждого):

| Секрет | Новое значение |
|---|---|
| `DEPLOY_HOST` | `5.182.87.217` |
| `DEPLOY_USER` | `deploy` |
| `DEPLOY_PATH` | `/home/deploy/zapchasti-qr` |
| `DEPLOY_KEY` | всё содержимое файла `zapchasti_deploy` (без `.pub`), включая строки `-----BEGIN…` и `-----END…` |

## 4. Адрес сайта

- **Если адрес остаётся прежним (свой домен):** у регистратора домена поменяйте A-запись на `5.182.87.217`. Телефоны и компьютеры перенастраивать не нужно, приложение само переключится, когда обновится DNS (обычно от 5 минут до часа).
- **Если адрес меняется** (например, был `…sslip.io` со старым IP): новый адрес будет `https://5-182-87-217.sslip.io`. Приложение на каждом телефоне придётся установить заново с нового адреса. Неотправленные операции со старого адреса не переедут, поэтому шаг 0 тут обязателен.

## 5. Запуск

GitHub → Actions → deploy → **Run workflow**. Через 2–3 минуты шаг «Проверить, что приложение отвечает» должен стать зелёным. Дальше каждое обновление в `main` будет приезжать само.

## 6. Проверка

Откройте сайт, войдите, проверьте остатки, журнал движений, фото и раздел «Закупка». Если всё на месте, старый сервер можно выключить. Сначала скопируйте себе последние файлы из его папки `backups/`.
