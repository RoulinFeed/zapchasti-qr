# Учёт запчастей по QR

Веб-приложение для склада запчастей к комбайнам: что где лежит, что у какой Газели и у какого механика, что и когда ставили на каждую технику. На Windows открывается в браузере, на Android ставится на главный экран как приложение и сканирует QR камерой. В поле работает без интернета, данные уходят на сервер, когда появляется связь.

## Как устроено

- `server/`: Node.js (Fastify) и PostgreSQL. Хранит журнал операций, выдаёт коды этикеток, следит за правами.
- `client/`: React, PWA. Локальная база в браузере (IndexedDB), очередь неотправленных операций, сканер QR (`qr-scanner`), печать этикеток.
- `shared/state.js`: общая логика. Остатки, паспорта техники и отчёты собираются из журнала операций одинаково на сервере и на телефоне.

Каждое действие (приход, перемещение, установка, снятие, списание, корректировка) записывается в журнал как отдельная операция с уникальным id. Операции только добавляются и никогда не меняются, поэтому повторная отправка ничего не дублирует, а работа без связи не приводит к конфликтам.

### Коды на этикетках

| Префикс | Что это |
|---|---|
| `P-000123` | Запчасть поштучного учёта (своя этикетка на каждую штуку) |
| `B-000045` | Партия или коробка (болты и прочая мелочь, учёт количеством) |
| `W-001` | Склад |
| `V-001` | Газель |
| `M-001` | Техника |
| `E-001` | Сотрудник |

В QR записан только код, всё остальное хранится на сервере, поэтому этикетка не устаревает.

### Роли

- **Механик**: перемещает, ставит на технику, снимает.
- **Кладовщик**: ещё делает приход, инвентаризацию, ведёт каталог и места, печатает этикетки.
- **Руководитель**: всё перечисленное и управление сотрудниками.

## Запуск на сервере

Нужен VPS с Docker (подойдёт самый маленький тариф) и домен, направленный на IP сервера. HTTPS обязателен: без него телефон не даст приложению доступ к камере. Сертификат Caddy получит сам.

```bash
git clone https://github.com/RoulinFeed/zapchasti-qr.git
cd zapchasti-qr
cp .env.example .env   # заполнить домен, пароль базы, логин и PIN руководителя
docker compose up -d --build
```

Администратор из `.env` создаётся при первом запуске. Резервные копии базы складываются в `backups/` раз в сутки, хранятся последние 30.

Фотографии запчастей хранятся в `data/photos/` на сервере, их архив тоже кладётся в `backups/` раз в сутки (последние 7).

Обновление: `git pull && docker compose up -d --build`.

## Разработка

```bash
npm run install:all
# PostgreSQL: база zapchasti, пользователь app/app (или своя строка в DATABASE_URL)
ADMIN_LOGIN=ruslan ADMIN_PIN=1234 npm start   # сервер на :3000
cd client && npm run dev                      # приложение на :5173, /api проксируется на :3000
```

Тесты:

```bash
npm test                                  # API и логика остатков (нужна база zapchasti_test)
cd client && npm run build && cd ../e2e && npm i && node smoke.mjs http://localhost:3000 && node sync.mjs http://localhost:3000
```

`e2e/smoke.mjs` проходит в браузере весь сценарий на пустой базе: места, приход, комплектацию Газели, установку на комбайн без связи, синхронизацию, остатки, инвентаризацию, пробную загрузку из Excel.
